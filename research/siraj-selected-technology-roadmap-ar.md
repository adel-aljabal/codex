# خارطة SIRAJ التقنية المنتقاة

**التاريخ:** 2026-09-20  
**الحالة:** المرجع المعتمد بدل تقارير تحليل مستودعات GitHub المرحلية (الدفعات 1–4)  
**النطاق:** SIRAJ OS · SIRAJ ATLAS · OpenClaw · Hermes · Codex · مسار الدخل

> القرار الحاكم: لا نضيف منصة ثانية تنافس SIRAJ Core، ولا نثبت أدوات ثقيلة قبل اكتمال ATLAS v0.4. نأخذ الأنماط المفيدة فقط، ونختبر كل إضافة كطيار صغير قابل للقياس والرجوع.

## 1. ما تحتاجه المعمارية الآن

### أولوية P0 — المسار الحرج

1. **إكمال ATLAS v0.4: Execution Trace + Flight Recorder**
   - تسجيل المهمة، الوكيل، الجهاز، المدخلات، الأدوات، القرار، الزمن، التكلفة، النتيجة، والأدلة.
   - دعم الاستئناف، المقارنة، والتراجع.
   - لا تبدأ تجارب تحسين أو منصات جديدة قبل checkpoint ناجح.

2. **عقد مهمة مشترك SIRAJ Task Contract**
   - مستلهم من `addyosmani/agent-skills` و`coleam00/context-engineering-intro`.
   - الحزمة المعيارية:

```text
task/
├── TASK.md
├── CONTEXT.md
├── ACCEPTANCE.md
├── PLAN.md
├── STATUS.json
├── evidence/
└── handoffs/
```

   - دورة الجودة: **Spec → Plan → Owner/Risk Gate → Build → Test → Review → Evidence → Ship**.
   - الحقيقة التشغيلية في Core API / Event Ledger، لا في ذاكرة محادثة وكيل منفرد.

3. **Capability Registry**
   - يسجل لكل وكيل: الجهاز، النموذج، الأدوات، المهارات، نوع المهام، التكلفة، القيود، الصلاحيات، وآخر اختبار ناجح.
   - Codex: المعماري والمنسق.
   - Hermes: منفذ محلي.
   - OpenClaw: أدوات وتنفيذ مجدول بعد فحص الجاهزية.
   - النماذج المحلية: المهام الخاصة أو منخفضة التكلفة.
   - SIRAJ Router هو صاحب قرار التوزيع.

4. **بوابات الموافقة والأدلة**
   - منع تغيير xKiro أو Endpoint أو API أو Default Provider دون موافقة.
   - منع الكتابة الخارجية، النشر، الرسائل، العمليات المالية، أو الأسرار دون Approval Gate.
   - كل نجاح يحتاج اختبارًا أو أثرًا داخل `evidence/`.

5. **Role Cards منتقاة فقط**
   - نستخلص من `msitarzewski/agency-agents` سبعة أدوار، ولا نثبت المكتبة كاملة:
     - Multi-Agent Systems Architect
     - Minimal Change Engineer
     - Code Reviewer
     - Privacy Engineer
     - RAG Pipeline Engineer
     - FinOps Engineer
     - Internationalization Engineer
   - كل Role Card تابع لسياسات SIRAJ ولا يملك صلاحية تغيير المزود أو المفاتيح.

6. **صيغة Skills موحدة**
   - اعتماد نمط حزم المهارات القابلة للتدقيق، مع `source_commit` و`license` واختبارات وصلاحيات محددة.
   - `microsoft/ai-agents-for-beginners` مرجع تحقق وتعليم فقط، وليس Runtime dependency.

## 3. المستقبل القريب — بعد نجاح v0.4

تنفذ التجارب التالية **بالترتيب**، تجربة واحدة في كل مرة:

### P1. LEANN — استرجاع دلالي محلي

- Pilot على مجلد صغير غير حساس.
- مكمّل للذاكرة وEvent Ledger، وليس بديلًا عنهما.
- يقارن مع `rg`/BM25 في: الاستدعاء، الدقة، زمن الاستجابة، الذاكرة، وحجم الفهرس.
- يُرفض إذا كان عبء RAM أو التعقيد أكبر من المكسب.

### P2. ECC / AgentShield — فحص أمني محدود

- مراجعة core profile فقط.
- لا تثبيت شامل أو عالمي.
- الهدف: كشف الأسرار، التعليمات الخطرة، والصلاحيات الواسعة قبل إدخال Skill أو Agent.

### P3. DSPy — مختبر التحسين

لا يبدأ إلا بعد توفر:

- Dataset صغير ممثل.
- Metric واضح.
- Baseline.
- Token/cost budget.
- سجل تجربة في Flight Recorder.
- Rollback.

يُستخدم لتحسين برنامج LM بالقياس، وليس كادعاء “تطوير ذاتي”.

### P4. Odysseus — مراجعة توافق واجهة فقط

- مرشح GUI لأن تجربة المستخدم الحالية موزعة.
- لا يثبت الآن على ASUS بسبب ضغط RAM وتداخل الذاكرة والمهام والوكلاء.
- أول خطوة: مراجعة `main` عند commit مثبت، Docker، المنافذ، auth، الأسرار، AGPL، والموارد.
- عند الاختبار: بيانات تجريبية، وتعطيل البريد وshell والجدولة.
- إذا اعتمد لاحقًا فيكون UI عبر SIRAJ Adapter، لا Core أو ذاكرة ثانية.

### P5. n8n — أتمتة أعمال خارج Core

- Workflow واحد read-only أولًا.
- النتيجة تعود إلى Event Ledger.
- مراجعة الترخيص والموارد.
- لا تشغيل حالي على ASUS؛ يقيّم بعد استقرار الموارد.

### P6. ClawFlows وVibeRaven — استخراج أنماط فقط

- من ClawFlows: Workflow schema وثلاثة تدفقات read-only كحد أقصى، بعد الفحص.
- من VibeRaven: readiness gates وevidence patterns فقط.
- لا تثبيت مباشر، ولا بناء Cockpit ثانٍ ينافس ATLAS.

## 4. مسار الدخل القريب

الأولوية التجارية ليست بناء SaaS كبير، بل بيع خدمة صغيرة واحدة قابلة للقياس:

### الخدمة المقترحة: تقرير ذكاء وسمعة لنشاط محلي

- جمهور البداية: منشأة ضيافة أو نشاط محلي في قطر.
- مخرجات شهرية عربية/إنجليزية:
  - رصد المصادر العامة والمراجعات.
  - ملخص السمعة والمشكلات المتكررة.
  - فرص تحسين الظهور المحلي/GEO.
  - توصيات عملية ومحتوى مقترح.
- مراجعة بشرية قبل التسليم.
- لا كشط لبيانات شخصية، ولا outreach آلي، ولا نشر تلقائي في أول Pilot.
- بعد أول عميل وقياس الوقت والجودة يمكن أتمتة الأجزاء المثبتة عبر SIRAJ/n8n.

`geo-seo-claude` و`software-income-playbooks` مصادر أفكار فقط؛ نعيد بناء التدفق داخل سياسات SIRAJ ولا ننفذ `curl | bash` أو نعتمد الادعاءات التسويقية.

## 6. ما أُخرج من الخطة

حُذفت من الخطة النشطة العناصر التالية لأنها لا تخدم المعمارية الحالية أو المستقبل القريب:

- `face_recognition`: حساسية حيوية وقانونية وعدم صلة بالمسار الحالي.
- فهارس APIs الضخمة من cporter202: ليست معمارية ولا ضمان جودة؛ تُراجع فقط عند ظهور حاجة محددة لمزود.
- `generative-ai-arbitrage`: تسويق إحالي وأسعار متغيرة ولا يتوافق مع سياسة عدم تغيير المزود.
- `ai-agent-tools` و`automate-for-growth`: قوائم/دورات تسويقية وضوضاء أعلى من القيمة الحالية.
- `screenshot-to-code` و`VibeTags`: لا حاجة قريبة.
- `LangChain`: يكرر طبقة التوجيه الحالية؛ لا يدخل Core.
- أي تثبيت شامل لـAgency Agents أو Skills أو Workflows.
- أي أداة تتطلب صلاحيات واسعة، `curl | bash`، أو كتابة مباشرة إلى الإنتاج.
- أي منصة بذاكرة أو Router أو Scheduler مستقل ينافس مصدر الحقيقة في SIRAJ.

إذا ظهرت حاجة جديدة، يبدأ التقييم من المشكلة ومعيار النجاح، لا من شهرة المستودع.

## 7. حدود الموارد وشروط التوقف

- لا توجد تثبيتات ثقيلة جديدة على ASUS قبل هبوط ضغط الذاكرة إلى مستوى مستقر.
- تجربة واحدة فقط في كل مرة.
- commit مثبت، Sandbox، بيانات غير حساسة، ومفاتيح تجريبية محدودة.
- توقف فوري عند:
  - ارتفاع غير مقبول في RAM/CPU.
  - ازدواج مصدر الحقيقة.
  - صلاحيات غير قابلة للتقليص.
  - غياب الترخيص أو الاختبارات.
  - عدم تحسن مقياس واضح.
  - تعارض مع Approval Gate أو GOV-009.

## 8. القرار النهائي

خارطة الطريق المختصرة هي:

1. **الآن:** ATLAS v0.4 + Flight Recorder + Task Contract + Registry + Gates.
2. **بعده مباشرة:** LEANN ثم فحص أمني محدود ثم DSPy.
3. **واجهات وأتمتة:** مراجعة Odysseus، ثم n8n read-only، دون تكرار Core.
4. **الدخل:** Pilot خدمة تقرير ذكاء وسمعة محلية قبل أي SaaS.
5. **الباقي:** خارج الخطة حتى تظهر حاجة قابلة للقياس.

هذا الملف هو مصدر القرار الوحيد لهذه المجموعة من المستودعات.
